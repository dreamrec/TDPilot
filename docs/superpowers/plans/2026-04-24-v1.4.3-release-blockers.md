## Chunk 1: Fix #1 — Plugin-install auth path

### Task 1: Fail-loud when auth required but no secret

**Why:** `.mcp.json` ships with `TD_MCP_REQUIRE_AUTH=1` and no `TD_MCP_SHARED_SECRET`. `install.sh` / `install.ps1` generate a secret, but the Claude Code plugin path reads `.mcp.json` directly and never invokes the installer — so the plugin install lands users in a misconfigured state where every authenticated request returns 401 and the failure mode is opaque.
```python
def verify_auth_config() -> None:
    """Fail loud if auth is required but no shared secret is resolvable.

    Prevents the common misconfiguration where `.mcp.json` ships with
    `TD_MCP_REQUIRE_AUTH=1` but the plugin install path never runs
    install.sh / install.ps1 to generate a secret. Without this check,
    the server starts happily and every authenticated request returns 401.
    """
    import os

    require = os.environ.get("TD_MCP_REQUIRE_AUTH", "0").strip().lower()
    if require not in ("1", "true", "yes"):
        return
    secret = os.environ.get("TD_MCP_SHARED_SECRET", "").strip()
    if secret:
        return
    raise RuntimeError(
        "TDPilot: TD_MCP_REQUIRE_AUTH=1 but TD_MCP_SHARED_SECRET is not set.\n"
        "Run the installer (install.sh or install.ps1) to generate one, "
        "or set TD_MCP_REQUIRE_AUTH=0 to disable auth (not recommended)."
    )
```

Then call `verify_auth_config()` at server startup (inside the main / `run` entry, before any transport starts).

## Chunk 2: Fix #2 — DocsBrain multi-word operator lookup

### Task 2: Correct `_op_type_map` construction

**Why:** `src/td_mcp/knowledge/docsbrain/__init__.py:52-58` builds the op_type map as `parts[0].lower() + parts[-1]`.
