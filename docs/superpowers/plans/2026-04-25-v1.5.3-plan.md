## In scope

### 1. Add a regression test for the auth-bootstrap ordering bug
**File:** `tests/test_auth_bootstrap.py` (extend existing file)
**Why:** Commit `8e8a598` fixed it but nothing prevents a future refactor from moving `bootstrap_auth()` back inside `main()`. The failure mode (TD_SHARED_SECRET frozen as None at module-load) is silent in unit tests because the module-level capture happens before any test runs.

**Approach:**
- New test fixture: writes a temp `.tdpilot.env` with a known secret, sets `TDPILOT_ENV_FILE` to point at it
- Imports `td_mcp.tool_registry` in a subprocess (fresh interpreter)
- Asserts `tool_registry.TD_SHARED_SECRET == <known_secret>`
- The subprocess matters: a within-process import would already have tool_registry cached from prior tests

**Acceptance:** test fails if `bootstrap_auth()` call is moved out of the pre-import block in `server.py`. Verify by temporarily commenting out the bootstrap line and confirming the test catches it.

**Estimated:** 30 minutes

### 2. `td_preflight_patch` → `patch.preview_plan` delegation
**File:** `src/td_mcp/registry/tools_planning.py:194` (the `TODO(v1.5.2)` we retagged)
**Why:** Two implementations of preflight validation drift apart over time. The MCP tool currently re-implements path/name-conflict checks the typed planner already does.

**Approach:**
- The signature mismatch is real: tool takes a dict, helper takes a typed `PatchPlan`. Need an adapter.
- Write `_dict_to_patch_plan(dict) -> PatchPlan` in `src/td_mcp/patch/planner.py` (or new `models/patch_adapter.py` if it grows)
- Replace the inline body of `td_preflight_patch` with: deserialize → `await preview_plan(client, plan)` → serialize the response
- Parity tests: snapshot `td_preflight_patch` outputs for 5+ representative input plans, then run both implementations and assert identical outputs (one-time test, then keep just the delegation test)

**Acceptance:**
- Existing `tests/test_planning_tools.py` and `tests/test_planning_tools_behavior.py` still pass without changes
- New `tests/test_planning_tools_delegation.py` verifies dict-input → preview_plan path produces same shape as legacy
- Comment removed: no more `TODO(v1.5.2)` in the file
- No behavior change observable to MCP callers

**Estimated:** 1.5–2 hours

### 3. Auto-snapshot before `apply_plan` (opt-out)
**File:** `src/td_mcp/patch/applier.py::apply_plan`
**Why:** Patch failures during multi-op application can leave the project in a half-applied state. The `services.snapshot_manager` already exists; just needs to be invoked before any op runs.

**Approach:**
- New parameter on `apply_plan(... auto_snapshot=True)`
- If True: call `snapshot_manager.create_snapshot(label=plan.undo_label or "auto_pre_apply")` before the for-op loop
- Store the snapshot id on `result.pre_apply_snapshot_id`
- Document: caller can revert via `td_restore_snapshot` using that id
- The TD-side `start_undo_block` is still the primary recovery path (faster, finer-grained); the snapshot is the fallback for catastrophic cases where undo fails

**Acceptance:**
- New test: `test_applier_auto_snapshot.py` confirms a snapshot is created before ops run, with id surfaced on result
- `td_patch_apply` MCP tool exposes the option (defaulting to True)
- `auto_snapshot=False` path verified to skip the snapshot call

**Estimated:** 1 hour

### 4. `_record_outcome` for `kind=macro` — surface created paths
**File:** `src/td_mcp/patch/applier.py::_record_outcome` (the macro branch)
**Why:** v1.5.0 deferred this. Macro expansion can create N nodes from one op; currently the result records only the macro op's metadata, not the nodes it actually created. Callers can't easily verify what landed.

**Approach:**
- The `MacroEngine.expand_and_apply()` (or whatever the v1.5.x equivalent is — check current signature) already returns a structure with created paths. Surface them.
- Extend the `elif op.kind == "macro":` branch in `_record_outcome` to set `result.created.extend(macro_response['paths'])` (exact key TBD by reading the engine's response shape)

**Acceptance:**
- Existing `test_macro_engine.py` still passes
- New assertion in `scripts/patch_session_smoke.py` step 7/13: `result.created` contains the expected number of paths after macro op

**Estimated:** 30 minutes

## Per-commit discipline (every item)

1. **Write the test FIRST** when the change is testable (TDD via `superpowers:test-driven-development` skill). This includes the parity tests in item 2.
2. **Run the test alone** to confirm it fails for the right reason, then implement.
3. **Run all 5 CI gates locally before committing:**
   - `.venv/bin/python -m pytest -q --no-header`
   - `.venv/bin/ruff check src tests scripts td_component`
   - `.venv/bin/ruff format --check src tests scripts td_component`
   - `.venv/bin/python scripts/check_versions.py`
   - `.venv/bin/python scripts/check_tox_freshness.py`
   - `bash scripts/check_no_personal_paths.sh`
4. **One conventional commit per item** with a body that explains the WHY, not just the WHAT. Reference the v1.5.3 plan path.
5. **Don't** modify `td_component/*.py` unless an item explicitly requires it — touching those forces a full TD-side `.tox` rebuild via Textport. v1.5.3 items 1–5 should NOT need this.
6. **Don't release.** This plan describes work, not a release. The release flow is below; only execute it on explicit instruction.

## Live-debug pitfalls to remember (full text in memory file)

If something breaks during v1.5.3 work, check the memory file's **Live-debug pitfalls** section. The four traps from v1.5.2 work:

- **A:** `bootstrap_auth()` must run before `tool_registry` imports (fixed in `8e8a598`; item 1 here adds the regression test)
- **B:** `~/.tdpilot/` venv installs non-editable; `cd ~/.tdpilot && uv pip install -e .` to make source edits visible
- **C:** `REQUIRE_AUTH=0` does NOT bypass auth when a secret is loaded — read `_check_auth_error` carefully before debugging auth
- **D:** Stale `.toe` at `~/.tdpilot/tdpilot_default.toe` runs old startup code; rename `.toe*` files and set `general.startupfilemode 0` in TD prefs
