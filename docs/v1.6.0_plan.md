# TDPilot v1.6.0 — Plan

**Status:** Draft / not yet implemented
**Author:** Strategic review 2026-05-02 (TwoZero competitive analysis)
**Tool count target:** 99 → 103 (+4 net new tools, 1 extension, 1 cross-cutting param add)
**Theme:** Make the agent feel TD-native — focus-aware, hint-injected, scoped-search, per-COMP notes — without building a parallel UI cockpit and without trading away the open-core differentiator.

---

## 0. Background

This plan is the output of a competitive review of [TwoZero](https://twozero.ai) and a strategic decision to **differentiate on rigor, not chase parity**. The full reasoning is in `skills/tdpilot-core/SKILL.md` §13 (Rules 1–3). Features we considered and intentionally deferred live in the local memory file `roadmap-future.md` (not committed to this repo).

**TDPilot's positioning:** rigor + auditability + open core (no signup, no key, `npx tdpilot` works).
**TwoZero's positioning:** speed-to-cool + cloud-coupled cockpit, opaque `.tox`.
**v1.6.0's job:** close the cold-start ergonomics gap (focus, hints, locations) without taking on cockpit-product maintenance.

## 3. Spec

### 3.1 `td_get_focus`

**File:** new tool in `src/td_mcp/registry/tools_state.py` (sits next to `td_get_state_vector`)
**TD-side endpoint:** new handler `focus` in `td_component/mcp_webserver_callbacks.py`
**Forwarding key:** `_tr._forward(ctx, "td_get_focus", "focus", payload)`

**Signature:**
```python
@mcp.tool(name="td_get_focus")
async def td_get_focus(
    ctx: Context,
    include_selection: Annotated[
        bool,
        Field(default=True, description="Include selected ops in active pane"),
    ] = True,
    include_pane_history: Annotated[
        bool,
        Field(default=False, description="Include last 5 pane paths"),
    ] = False,
) -> dict[str, Any]:
    """Return where the user currently is in TouchDesigner: active network pane, selection, project meta."""
```

**Return shape:**
```json
{
  "active_pane_path": "/project1/render_chain",
  "active_pane_type": "NetworkEditor",
  "selected_ops": ["/project1/render_chain/feedback1", "/project1/render_chain/over1"],
  "selected_first": "/project1/render_chain/feedback1",
  "project_name": "live_visuals_v3.toe",
  "td_build": "2025.32460",
  "fps_target": 60.0,
  "timeline_state": "playing",
  "pane_history": ["/project1", "/project1/audio", "/project1/render_chain"]
}
```

**TD-side logic:**
- `ui.panes.current` for active pane
- `pane.owner.path` for path
- `ui.panes.current.owner` selected children via `.selectedChildren`
- `project.name`, `app.build`, `app.osName`
- `me.fps`, `me.timeline.state`

**Why it compounds with rigor:** Eliminates the "what path are you editing?" cold-start friction that currently makes the agent ask for paths before every patch. Reduces the chance of patch operations targeting the wrong subnet.

**Edge cases:**
- No active pane (TD just opened, no project) → `active_pane_path = "/"`, `selected_ops = []`
- User in a non-network pane (Animation Editor, Component Editor) → `active_pane_type` reflects this; agent should not assume `active_pane_path` is a valid network root

### 3.2 `td_locations(action=...)`

**File:** new tool in `src/td_mcp/registry/tools_state.py` (alongside `td_get_focus`)
**TD-side endpoint:** new handler `locations` (single endpoint, dispatches on `action`)
**Storage:** `~/.tdpilot/locations/<project_hash>.json` — one file per project (project hash = sha256 of absolute project path, first 12 chars)

**Signature (single-tool dispatcher pattern):**
```python
@mcp.tool(name="td_locations")
async def td_locations(
    ctx: Context,
    action: Annotated[
        str,
        Field(description="One of: save, list, go, delete, rename"),
    ],
    name: Annotated[
        str | None,
        Field(default=None, description="Location name (required for save/go/delete/rename)"),
    ] = None,
    new_name: Annotated[
        str | None,
        Field(default=None, description="New name (rename action only)"),
    ] = None,
    path: Annotated[
        str | None,
        Field(default=None, description="Override path (default: use td_get_focus result)"),
    ] = None,
    description: Annotated[
        str | None,
        Field(default=None, description="Optional human-readable note (save action)"),
    ] = None,
) -> dict[str, Any]:
    """Save, list, jump-to, or delete named network locations per-project."""
```

**Storage schema (per-project JSON):**
```json
{
  "project_hash": "a3f7c1...",
  "project_path": "/Users/foo/projects/live_visuals_v3.toe",
  "locations": [
    {
      "name": "feedback_lab",
      "path": "/project1/feedback_chain",
      "scroll": [120.5, -45.0],
      "zoom": 1.4,
      "description": "Where I'm tuning the feedbackTOP chain",
      "created_at": "2026-05-02T14:30:00Z",
      "updated_at": "2026-05-02T14:30:00Z"
    }
  ]
}
```

**Action semantics:**
- `save` — capture current `td_get_focus` (or override `path`), persist with `name`. Overwrites if name exists.
- `list` — return all locations for current project; `[]` if none.
- `go` — jump network editor to the named location's path + scroll + zoom. Returns `{success: bool, jumped_to: "/path"}`.
- `delete` — remove by `name`.
- `rename` — change `name` → `new_name`.

**Why it compounds with rigor:** Per-project state. Doesn't pollute global memory. Survives session restarts. Pairs with `td_get_focus` to give the agent + user a shared spatial vocabulary for big projects.

### 3.3 `td_search_nodes` scopes extension

**File:** modify `src/td_mcp/registry/tools_data.py:276-303` and the `SearchNodesInput` Pydantic model.
**TD-side endpoint:** existing `search` handler — extend to support new `scopes` payload field. Backward compatible.
**Forwarding key:** unchanged (`_tr._forward(ctx, "td_search_nodes", "search", payload)`).

**Migration:**
```python
# OLD:
search_type: Annotated[str, Field(default="all")] = "all"  # 'name'|'type'|'family'|'all'

# NEW:
scopes: Annotated[
    list[str] | None,
    Field(
        default=None,
        description="Search scopes: 'name', 'type', 'family', 'dat_text', 'param_values', "
                    "'param_exprs', 'errors', 'comments', 'notes'. Default: ['name','type','family'].",
    ),
] = None
search_type: Annotated[  # DEPRECATED — kept for backward compat
    str | None,
    Field(default=None, description="DEPRECATED — use 'scopes' instead. Maps to single-element scope."),
] = None
```

**Validator behavior (in `SearchNodesInput`):**
- If `scopes` is None and `search_type` is None → default to `["name", "type", "family"]`
- If `search_type` is set and `scopes` is None → map: `"all"` → `["name","type","family"]`, others → `[search_type]`
- If both set → `scopes` wins, log deprecation warning
- Validate every scope is in the allowed set

**Return shape (extended, backward-compatible):**
Each result row gains a `scope` and `match_field` to clarify why it matched:
```json
{
  "results": [
    {"path": "/project1/audio1", "type": "audiofileinCHOP", "scope": "type", "match_field": "type"},
    {"path": "/project1/text1", "type": "textDAT", "scope": "dat_text",
     "match_field": "content", "snippet": "...op('audio1').par.file..."}
  ],
  "total": 12,
  "scopes_searched": ["name", "type", "family", "dat_text"]
}
```

**TD-side scope handlers (in `mcp_webserver_callbacks.py`):**
- `name` / `type` / `family` — existing logic
- `dat_text` — iterate text DATs under `path`, regex match `query` against `.text`
- `param_values` — iterate ops under `path`, match against string values of all parameters
- `param_exprs` — iterate ops under `path`, match against `.expr` of all parameters
- `errors` — iterate ops under `path`, match against `.errors`
- `comments` — match against `op.comment`
- `notes` — match against component_notes (see §3.6) — searches both DAT-embedded notes and external storage

**Why it compounds with rigor:** Replaces the proposed `td_search_project` (which would have been a duplicate tool). One tool, more power, no surface inflation. The `notes` scope ties §3.6 into the existing search workflow without a separate tool.

### 3.4 `td_get_hints(topic, op_type, intent)`

**File:** new file `src/td_mcp/registry/tools_hints.py` (new registry module)
**TD-side endpoint:** **none** — this is a host-side orchestrator over existing knowledge tools + bundled hint packs. Does NOT touch TD.
**Backing data:** `src/td_mcp/hints/packs/*.yaml` (new directory) + reads from `tools_knowledge.py` + reads from `tools_knowledge_store.py` + reads `skills/tdpilot-core/SKILL.md` pitfalls

**Signature:**
```python
@mcp.tool(name="td_get_hints")
async def td_get_hints(
    ctx: Context,
    topic: Annotated[
        str | None,
        Field(default=None, description="Topic name: 'glsl', 'feedback', 'audio_reactive', "
                                        "'extensions', 'recording', 'panel_ui', 'custom_parameters', "
                                        "'pop', 'popx', 'render_pipeline', 'macros'"),
    ] = None,
    op_type: Annotated[
        str | None,
        Field(default=None, description="OP type to get type-specific hints (e.g., 'glslTOP', 'feedbackTOP')"),
    ] = None,
    intent: Annotated[
        str | None,
        Field(default=None, description="What you're about to do (free-text). Used for hint scoring."),
    ] = None,
    node_path: Annotated[
        str | None,
        Field(default=None, description="Optional: path of node about to be modified (enables context-aware hints)"),
    ] = None,
    max_hints: Annotated[
        int,
        Field(default=8, ge=1, le=20),
    ] = 8,
) -> dict[str, Any]:
    """Return concise, source-cited hints for a topic, op_type, or intent. Sources: official brain,
    POPx/Paketa12 brains, tdpilot-core pitfalls, knowledge_store, and hint packs."""
```

**Return shape:**
```json
{
  "topic": "feedback",
  "op_type": "feedbackTOP",
  "confidence": 0.87,
  "hints": [
    {
      "priority": "critical",
      "rule": "feedbackTOP cycles produce 'Not enough sources' static-analyzer warnings — screenshot before assuming broken",
      "source": "tdpilot-core §11",
      "source_kind": "skill_pitfall"
    },
    {
      "priority": "useful",
      "rule": "Use 'level.opacity' on Post page for trail decay, NOT 'brightness1'",
      "source": "knowledge_store:af2f35ac",
      "source_kind": "user_essay"
    },
    {
      "priority": "context",
      "rule": "fb.par.top points at compositor (over), not final out",
      "source": "derivative_palette",
      "source_kind": "official_doc"
    }
  ],
  "next_tools": ["td_get_param_help", "td_get_errors"],
  "hint_pack_version": "v1.6.0-1"
}
```

**Routing rules (in order):**
1. If `op_type` set → load `packs/op_types/<op_type>.yaml` if exists
2. If `topic` set → load `packs/topics/<topic>.yaml`
3. Always: query `tools_knowledge.py:td_search_official_docs(intent)` for top 2 doc snippets
4. Always: query `tools_knowledge_store.py:td_knowledge_recall(intent)` for top 2 user essays
5. Always: scan `skills/tdpilot-core/SKILL.md` §11 (Render Pipeline Pitfalls) for matches against `op_type`/`topic`
6. Score, dedupe, truncate to `max_hints`. Critical priority always wins ties.

**Why this is a thin orchestrator, not a new system:** No new storage, no new schema beyond hint packs. All sources already exist. The novelty is **routing + ranking + auto-injection** (§3.5).

### 3.5 Hint injection on high-risk tools

**Files:** modify these tools in-place (no new tools):
- `td_create_node` — `src/td_mcp/registry/tools_data.py` (write side)
- `td_set_params` — `src/td_mcp/registry/tools_content.py`
- `td_exec_python` — `src/td_mcp/registry/tools_runtime.py`
- `td_get_errors` — `src/td_mcp/registry/tools_data.py`
- `td_plan_patch` — `src/td_mcp/registry/tools_planning.py`
- `td_patch_preview` — `src/td_mcp/registry/tools_patch.py`

**New parameter (added to each):**
```python
include_hints: Annotated[
    bool,
    Field(default=False, description="Include relevant hints from td_get_hints in the response"),
] = False
```

**Auto-injection rules (apply even when `include_hints=False`):**
| Tool | Trigger pattern | Action |
|---|---|---|
| `td_create_node` | `op_type in {"glslTOP","feedbackTOP","moviefileoutTOP","extensionDAT","panelCOMP"}` | Auto-inject hints for that op_type |
| `td_set_params` | param name matches `^(instanceop\|material\|camera\|lights\|geometry\|top\|chop\|sop\|dat\|comp)$` AND value is a string | Inject "use OP reference, not string" hint |
| `td_exec_python` | code contains `op(` AND `restricted_exec` mode active | Inject restricted-exec workaround hint |
| `td_get_errors` | error text contains `"Not enough sources"`, `"extension"`, `"missing input"` | Inject targeted hint for that error class |
| `td_plan_patch` / `td_patch_preview` | plan touches feedback / GLSL / render chain | Inject pipeline-pitfalls hint |

**Response shape change (additive, non-breaking):**
```json
{
  // ...existing response keys unchanged...
  "hints": {  // present only when include_hints=True OR auto-trigger fired
    "auto_triggered": true,
    "trigger_reason": "op_type=feedbackTOP",
    "items": [ /* same shape as td_get_hints.hints */ ]
  }
}
```

**Why this is the actual UX win:** Hints arrive at the moment of risk without the agent having to remember to ask. This is the single biggest "feels TD-native" improvement in the whole plan.

**Capability flag:** Add `hint_injection_v1` to `td_get_capabilities()` so old `.tox` builds advertise their absence and the agent can degrade gracefully.

### 3.6 `td_component_notes(action=...)`

**File:** new tool in new file `src/td_mcp/registry/tools_notes.py`
**TD-side endpoint:** new handler `component_notes` (only used for the optional DAT-embed mode)
**Default storage:** `~/.tdpilot/component_notes/<project_hash>.json` (external — no .toe bloat by default)
**Optional storage:** hidden child Text DAT named `tdpilot_notes` inside the COMP (opt-in via `embed=True`)

**Signature:**
```python
@mcp.tool(name="td_component_notes")
async def td_component_notes(
    ctx: Context,
    action: Annotated[
        str,
        Field(description="One of: get, set, append, delete, summarize, index"),
    ],
    path: Annotated[
        str | None,
        Field(default=None, description="COMP path (required for get/set/append/delete; "
                                        "omit for index/summarize over the whole project)"),
    ] = None,
    body: Annotated[
        str | None,
        Field(default=None, description="Note text (markdown). Required for set/append."),
    ] = None,
    embed: Annotated[
        bool,
        Field(default=False, description="If True, also write to a hidden child Text DAT for portability"),
    ] = False,
    tags: Annotated[
        list[str] | None,
        Field(default=None, description="Optional tags for indexing/search"),
    ] = None,
) -> dict[str, Any]:
    """Per-COMP knowledge — what this subnet does, why it's wired this way, gotchas, TODO."""
```

**Storage schema (external JSON):**
```json
{
  "project_hash": "a3f7c1...",
  "project_path": "/Users/foo/projects/live_visuals_v3.toe",
  "notes": {
    "/project1/feedback_chain": {
      "body": "Reaction-diffusion approximation. Trail decay via level.opacity (0.92), NOT brightness.",
      "tags": ["feedback", "rd", "live"],
      "embedded": false,
      "created_at": "2026-05-02T14:30:00Z",
      "updated_at": "2026-05-02T14:30:00Z"
    }
  }
}
```

**Action semantics:**
- `get` — return note for `path` (and embedded version if both exist + flag drift)
- `set` — write/overwrite. If `embed=True`, also write hidden Text DAT inside COMP.
- `append` — append `body` to existing note (with timestamp separator)
- `delete` — remove note
- `summarize` — for `path` (subtree) OR whole project, produce markdown summary of all notes
- `index` — return `[{path, body_excerpt, tags, updated_at}, ...]` for search/discovery

**Integration with §3.3:** `td_search_nodes(scopes=["notes"])` returns matching note paths.
**Integration with `td_get_node_detail`:** Add new param `include_notes=False` so node detail surfaces relevant notes when requested. (NOT auto-injected — keeps default response sizes stable.)

**Why default-external storage:** DAT-embed bloats `.toe` save files and pollutes diffs for users versioning their TD projects. External-by-default keeps notes lightweight; opt-in embed for users who want notes to travel with `.tox`.

## 4. Hint pack schema

**Location:** `src/td_mcp/hints/packs/`
**Format:** YAML
**Two flavors:** `topics/<topic>.yaml` (broad), `op_types/<op_type>.yaml` (narrow)

**Schema:**
```yaml
# src/td_mcp/hints/packs/topics/feedback.yaml
schema_version: 1
topic: feedback
op_types: [feedbackTOP, feedbackEdgeTOP]
hints:
  - id: feedback_canonical_chain
    priority: critical
    rule: |
      Use canonical chain: src → fb (in 0); src → over (in 0 BG); fb → level → over (in 1 OVERLAY) → out.
      fb.par.top = over (compositor, NOT final out).
    source: tdpilot-core §11
    source_kind: skill_pitfall
    when:
      op_type: feedbackTOP

  - id: feedback_static_analyzer_warning
    priority: useful
    rule: |
      "Not enough sources specified" is a static-analyzer cycle warning, not a runtime error.
      Screenshot output before assuming broken.
    source: tdpilot-core §11
    source_kind: skill_pitfall
    when:
      op_type: feedbackTOP
      error_match: "Not enough sources"

  - id: feedback_trail_decay
    priority: useful
    rule: Trail decay is level.opacity on Post page (NOT brightness1). 0.9 = ~10% decay/frame.
    source: knowledge_store:af2f35ac
    source_kind: user_essay
    when:
      op_type: feedbackTOP
      intent_match: "decay|trail|fade"

next_tools: [td_get_param_help, td_screenshot, td_get_errors]
```

**Pack versioning:** Each pack carries a `schema_version`. The hint pack DIRECTORY carries an aggregate version returned in `td_get_hints` responses (`hint_pack_version: "v1.6.0-1"`) so future schema changes are detectable.

**Initial packs to ship in v1.6.0:**
- `topics/`: feedback, glsl, audio_reactive, render_pipeline, extensions, panel_ui, custom_parameters, pop, popx, recording, macros
- `op_types/`: feedbackTOP, glslTOP, glslMAT, moviefileoutTOP, extensionDAT, panelCOMP, audiofileinCHOP, geometryCOMP

2. **Auto-injection opt-out.** Should there be an env var (`TD_MCP_DISABLE_HINT_INJECTION=1`) for users who find injection noisy? **Recommended: yes**, default off. Cheap insurance.
3. **`td_locations` storage portability.** If a user copies a `.toe` to a new path, the project_hash changes and locations are lost. Mitigation: store both `project_path` and `project_name` and offer fuzzy match on rename. Or: `td_locations(action=migrate, from_path=..., to_path=...)`. **Defer until reported.**
4. **Component notes embedded vs external drift.** When `embed=True` and external both exist, which wins on read? **Recommended: external is authoritative**, embedded is a snapshot. Surface drift as a warning, don't auto-resolve.
5. **`td_get_node_detail` notes integration.** Add `include_notes=False` param this release, or defer? **Recommended: add it** — the surface change is trivial and the notes feature is undersold without it.
