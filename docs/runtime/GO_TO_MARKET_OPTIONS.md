# Deployment Model Options

## A. Open Research Architecture

Pros:

- fastest ecosystem adoption
- community validation loop
- stronger standards influence

Risks:

- weaker monetization moat

## B. Proprietary Studio Runtime

Pros:

- maximum product control
- direct monetization leverage

Risks:

- slower ecosystem trust and integration

## C. Hybrid (Open Core + Advanced Modules)

Pros:

- ecosystem reach plus premium differentiation
- practical path to category leadership

Risks:

- requires clear module boundaries and governance

## Recommendation

Use Hybrid:

- open core for runtime protocol and essential tools
- advanced memory/autonomy modules as premium layers

## Suggested Module Boundaries

Open core:

- MCP transport + tool registry
- graph editing and diagnostics
- safety bounds and snapshots
- runtime dashboard and base assessment

Advanced modules (candidate premium):

- preference learning automation
- advanced optimizer policies (sampling-aware search)
- high-level DOP packs (studio presets, custom intent vocabularies)
- production telemetry and performance analytics bundles
